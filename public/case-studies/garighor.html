01 — The Brief

A showroom website that actually works for the owner

The brief was simple but broad: build a production-ready website for a Chattogram-based reconditioned car dealership that could be handed directly to the showroom owner to run his business — no developer involvement required for day-to-day use.

That meant solving three distinct problems simultaneously: a public customer site that builds trust and drives enquiries, a private admin console where non-technical staff can manage inventory, and a system that doesn't let leads fall through the cracks at 11 PM when nobody's watching the inbox.

"Most dealership websites are digital brochures. A customer gets curious, doesn't get an answer fast enough, and leaves. I built something that captures them instead."

Customer needs

Browse real inventory with prices, save favourites, submit enquiries and test-drive requests, and get instant AI assistance at any hour.

Owner needs

Add/edit/delete car listings, upload photos, view all customer enquiries in one place, and never manually transcribe a phone number from a chat log again.

02 — Technical Stack

Every choice justified, every layer understood

No boilerplate generators, no starter kits. Every file in this project was written by hand, including the Prisma schema, all Express middleware, and the entire 1,686-line React application.

Frontend

React 18 Vite Lucide React CSS-in-JS

Single-file React app (App.jsx). No component library — every UI element styled inline for full control and zero dependency bloat.

Backend

Node.js Express.js Prisma ORM JWT Auth bcrypt Multer

RESTful API with JWT-protected admin routes, bcrypt password hashing, rate limiting, and async error handling that prevents server crashes.

Database & Storage

Neon PostgreSQL Cloudinary

Serverless Postgres via Neon with Prisma migrations. Car photos stored on Cloudinary's free tier — persists through server restarts where local disk storage would not.

AI Layer

Google Gemini 3.6 Flash Structured Output responseSchema

Gemini API with responseMimeType: "application/json" forces typed JSON on every response — no regex parsing of free text.

Infrastructure

Vercel Render GitHub CI/CD UptimeRobot

Frontend on Vercel (auto-deploys on push). Backend on Render free tier, kept alive via UptimeRobot 5-minute pings. Migrations run at build time, not at startup, to eliminate cold-start latency.

Backup System

pg_dump adm-zip Task Scheduler

Custom Node.js backup script: daily pg_dump of the live database + zipped Cloudinary uploads, stored to an external drive. Restore tested against a live Neon branch — verified, not assumed.

The structured output schema

The core technical decision: using responseSchema in the Gemini API call to force a typed JSON response on every single message — not just when the model decides to use a "tool." This means the backend always receives a predictable structure it can parse and act on, regardless of what the customer said.

// backend/src/routes/chat.js — RESPONSE_SCHEMA
const RESPONSE_SCHEMA = {
  type: "OBJECT",
  properties: {
    replyToUser:    { type: "STRING"  },  // shown to customer
    triggerBooking: { type: "BOOLEAN" },  // true only when all fields collected
    bookingDetails: {
      type: "OBJECT",
      properties: {
        customerName:       { type: "STRING" },
        contactInfo:        { type: "STRING" },
        appointmentDateTime:{ type: "STRING" },
        vehicleStockNo:     { type: "STRING" },
      }
    },
    financingRequest: { type: "OBJECT" }  // EMI calculator trigger
  },
  required: ["replyToUser", "triggerBooking"]
};

Code-enforced validation — not prompt-enforced

The system prompt asks the model to verify contact completeness. But LLM compliance is probabilistic. So the backend enforces it again in code — independently of what the model decided — before anything touches the database.

// contact validation — server-side, never trusts the model alone
function isValidContact(contactInfo) {
  const trimmed = contactInfo.trim();
  const emailLike = /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(trimmed);
  const digitsOnly = trimmed.replace(/\D/g, "");
  const phoneLike  = digitsOnly.length >= 7
                  && digitsOnly.length <= 15
                  && /^[\d\s+\-()]+$/.test(trimmed);
  return emailLike || phoneLike;
}

🔒 Duplicate lead prevention

A dedup query checks for a lead with the same name, car, and source created in the past 10 minutes before writing a new row. Scoped by source so demo testing never blocks real customer bookings.

🔁 Automatic retry on 503

Gemini's free tier occasionally returns 503 "high demand" errors. The backend retries automatically up to 3 times with 1s/2s backoff — verified with a mock fetch test — so brief spikes are invisible to the customer.

📊 Real failure feedback

Each outcome has a specific reply: invalid_contact asks them to re-check, db_error gives them a direct phone number, duplicate keeps the confirmation. The customer is never told "booked" when nothing was saved.

💰 EMI calculator

If a customer states a down payment amount, the backend computes an actual monthly estimate using real car price data and a configurable interest rate — appended to the reply without the model inventing a number.

🛡️ Graceful fallback — the AI is an interface, not a single point of failure

A critical architectural upgrade: recognising that a Gemini 503 error should never mean a lost lead. The system now has two independent paths to the same outcome — the LLM and a structured form — both posting to the exact same /api/leads Node.js endpoint. 

             ┌── Gemini AI ─────────────────────┐
Customer ────┤                                  ├──→ POST /api/leads ──→ PostgreSQL
             └── Fallback Booking Form ─────────┘                           │
                                                                             ↓
                                                                      Admin Dashboard

When Gemini is unavailable, the chat widget surfaces a 4-step booking wizard inline — no redirect, no new page — collecting vehicle, date/time, name, and contact, then posting directly to the backend. The dealer's dashboard sees the same structured lead either way. The AI never appears in the data path, only in the user experience.

"The AI is an interface. The backend is the source of truth. That's the architecture I'd bring to your project."

🔁 Auto-retry before fallback

Before showing the fallback, the backend retries Gemini up to 3 times (1s/2s backoff). Brief demand spikes recover invisibly — only genuine outages reach the customer.

📋 4-step booking wizard

Guaranteed structured capture: Vehicle → Date/Time → Name → Contact → Confirm. Posts to /api/leads directly — same table, same admin dashboard, zero AI dependency.

05 — Problems Found & Fixed

What real-world testing actually surfaces

A portfolio project that never encountered real problems proves nothing. These are bugs that appeared during actual use — each one diagnosed from real evidence, not guessed at.

AI

Incomplete contact info accepted

Gemini set triggerBooking: true when a customer gave "prasomiy" as an email. Code-level regex validation added — the model's verdict is now double-checked independently before any database write.

AI

Duplicate leads on confirmation

When a customer said "yes, that's right" after booking, the model re-emitted triggerBooking: true, creating duplicate rows. A 10-minute dedup window added per name + car + source combination.

Backend

Server crash on unhandled async errors

Express 4 doesn't catch errors thrown inside async route handlers — a single bad request could take down the whole process. An asyncHandler wrapper added to every route to forward rejections to the central error handler.

Backend

Migration running on every cold start

prisma migrate deploy was in the Start Command, adding real latency to every wake-up. Moved to the Build Command — migrations run once per deploy, not once per request.

Frontend

Wishlist showing wrong count

Wishlist IDs in localStorage became stale when cars were deleted or re-seeded. On load, saved IDs are now reconciled against live inventory — phantom saves pruned automatically, only if the cars fetch succeeded (guarded against network failures).

Frontend

Markdown rendering in chat

Gemini replies with **bold** and - bullets even when told not to. A lightweight renderer added — splits on bold patterns, maps -  prefix lines to bullet divs — no markdown library needed.

Infra

Gemini 503 — high demand errors

Render logs showed repeated 503s ("model currently experiencing high demand") during a testing session. Automatic retry with exponential backoff (1s, 2s, max 3 attempts) added — verified with a mock fetch test.

Infra

Missing database table

The Setting model (for the hero image feature) was added to schema.prisma but the migration was never generated — the live route returned 404. Caught by actually hitting the endpoint and reading the error, not by inspection alone.

Architecture

AI as single point of failure

Gemini 503 errors were silently dropping leads — if the AI failed mid-booking, the customer got an error message and the lead was lost. Fixed by separating the LLM (conversational interface) from the backend (source of truth): the chat widget now falls back to a structured booking wizard that posts to /api/leads directly. Two independent paths, same database, same admin view.

Architecture

Non-deterministic demo experience

A multi-turn Gemini conversation is probabilistic — showing it to a recruiter depends on the AI successfully maintaining context across several messages. Fixed with a guaranteed 4-step booking wizard in the demo console that always works, alongside the AI chat. The recruiter can test the deterministic path even when Gemini has high demand.

07 — The Pitch

What this demonstrates for any business

GariGhor Motors was built as a portfolio piece. But the architecture underneath it — an AI assistant that captures qualified leads directly into a structured database, without a human in the loop — applies to any business where customer conversations currently end without a record.

The technical pitch in plain language

When a customer speaks to the AI on this platform, the model doesn't just chat. It acts as an active data collector. The moment the user expresses intent to buy or book, the code forces Gemini to output a strict JSON schema — locking fields for name, contact, date, and vehicle. My Node.js backend validates that data independently of what the model decided, cross-references it against live inventory, prevents duplicates, and writes a structured lead row to PostgreSQL. The dealer opens their dashboard the next morning to a ready-to-call lead, correctly attributed, with no manual work anywhere in the chain.

I can build this exact automated pipeline for any business with customer conversations that currently end without a record: clinics, real estate agencies, event booking, service businesses — anywhere a lead falling through at 9 PM costs money.
